Trace scoring — calibration

Not shipped: this page exists so the four numbers in WRITE are set from a measurement rather than from taste. It reads them out of js/write.js and calls the real wScore(), so it calibrates the scorer the app runs, not a copy of it. Eight synthetic traces are put over all 24 letters. middle, jitter 5 and tail should pass; oversize, scribble and line should not; the two heavier jitters are the boundary and may go either way. tail is the reported bug — the letter followed properly, then a fifth of the ink run off the bottom. It should still pass, but it must not read in the nineties, which is what it used to do. The guide is drawn in whatever serif the machine resolves, so absolute numbers shift a little between devices; the gap between the groups is what matters.
